HTTP 缓存的核心概念

1. HTTP 缓存的基本原理

HTTP 缓存通过在浏览器或代理服务器中存储资源副本，减少对源服务器的请求。缓存主要分为强缓存和协商缓存。

核心机制：
  • 强缓存：通过 Expires 或 Cache-Control 告诉浏览器在有效期内直接使用本地副本，无需请求服务器。
  • 协商缓存：通过 Last-Modified/If-Modified-Since 或 ETag/If-None-Match 进行核对。若资源未变，服务器返回 304 Not Modified，减少数据传输。

例子：当浏览器首次加载一张图片，服务器返回 Cache-Control: max-age=3600。在一小时内，浏览器再次访问该图片时，会直接从磁盘读取，不会发送网络请求。

误区：认为缓存仅仅是把文件存起来，而忽略了缓存是有“新鲜度”（Freshness）和“验证”（Validation）机制的。

总结

缓存是提升性能的关键。理解强缓存与协商缓存的区别，能够帮助开发者在静态资源更新与性能优化之间取得平衡。
