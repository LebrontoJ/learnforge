HTTP 缓存的核心概念

1. HTTP 缓存的基本原理

HTTP 缓存通过将资源存储在靠近客户端的位置（如浏览器缓存或代理服务器），避免重复请求远端服务器。它依赖于 HTTP 响应头部的指令来决定资源是否可以被存储、以及何时过期。核心分为强缓存（Expires/Cache-Control）和协商缓存（ETag/Last-Modified）两个阶段。

例子：假设你访问一个图片，浏览器第一次请求后将其存在本地。第二次访问时，检查 Cache-Control 发现未过期，直接从本地加载，无需发起网络请求。

误区：误以为所有资源默认都会缓存，实际上缓存策略完全取决于服务器响应头与浏览器的特定实现。

2. 总结

HTTP 缓存是优化 Web 性能的关键。通过合理配置强缓存减少请求次数，使用协商缓存确保内容时效性，可以显著降低带宽消耗并提升加载速度。
