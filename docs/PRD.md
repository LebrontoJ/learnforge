# AI 技术自学平台需求文档

版本：V1.0 草案
日期：2026-10-22
产品形态：面向桌面与移动浏览器的 Web 应用
当前优先级：先完成可展示、可评测的交互教学内容生成闭环，再扩展练习、复习与音频。

## 1. 产品定义与目标

用户输入希望学习的技术或知识概念，以及可选的学习目标和已有基础。平台通过 Agent 的知识理解、Web Search 和资料读取能力，生成课程大纲，并按用户选择生成 HTML 学习讲稿。适合交互演示的内容可以包含可操作的模拟、图示或小工具。

平台在隔离环境中运行生成内容，利用浏览器操作、运行日志与独立检查规则发现问题，并在限定次数内修复。用户随后可手动生成练习、安排复习或生成适合通勤收听的音频。

产品支持开放技术主题，不将用户输入限制在某个领域。首版通过固定的跨主题案例集评测系统能力；评测覆盖范围不等于产品支持范围。

### 1.1 用户价值

- 将模糊的学习意图转化为清晰、可调整的学习路径。
- 用讲解、示例和可操作演示帮助用户理解抽象概念。
- 提供资料来源、技术版本和验证状态，帮助用户判断内容可信程度。
- 让用户按自己的节奏选择练习、复习与收听。

### 1.2 项目能力目标

Milestone 1 优先形成三项相对现有求职助手项目的新能力证据：

1. 将自然语言学习需求转化为结构化教学规格与可运行交互页面。
2. 通过真实浏览器执行获取反馈，驱动有限次数的局部代码修复。
3. 使用独立规则与固定案例评测生成结果，比较质量收益、耗时和成本。

MCP、搜索、异步任务和引用核验是支持这些目标的基础设施，不作为首版唯一技术亮点。

### 1.3 非目标

- 首版不建设通用云端 IDE 或完整应用生成平台。
- 首版不执行用户提交的任意后端程序，不提供真实 Kubernetes 集群实验。
- 不承诺任意技术主题都能生成正确的交互模拟。
- 不将页面运行成功等同于技术内容正确或学习效果提升。
- 不自动替用户创建练习、复习计划或音频。

## 2. 用户与典型场景

目标用户：学习新技术、准备面试或补充基础知识的开发者与计算机相关专业学生。

| 场景 | 输入示例 | 预期结果 |
| --- | --- | --- |
| 理解算法 | 我想理解二分查找，基础一般 | 可逐步操作的搜索演示、解释与边界案例 |
| 理解系统机制 | 我想理解 LRU 缓存淘汰 | 可修改容量和访问序列的演示 |
| 学习技术工具 | 我会 Docker，希望学习 K8s 部署与排障 | 分阶段课程、版本说明、配置示例；合适章节提供简化模拟 |
| 理解监控指标 | 学习 Prometheus counter、rate 与采样 | 基于明确模拟数据的图示和交互解释 |
| 巩固知识 | 对当前章节生成五道情境题 | 用户主动触发的练习集和解析 |
| 通勤复习 | 将最近选中的知识点生成十分钟音频 | 经用户确认的听觉讲稿与音频 |

## 3. 核心原则与操作边界

### 3.1 用户控制

- 每次生成练习、创建复习计划、合成音频，必须来自对应的显式操作。
- 用户发起一次讲稿生成后，系统可自动执行该任务内部的检索、生成、验证和有限修复，无需逐步确认。
- 重新生成已有内容必须说明影响范围，保留旧版本。
- 阅读完成、答错、复习到期、音频播完，不触发新的生成任务。

### 3.2 可靠性边界

- 模型知识用于组织和解释；涉及版本敏感行为、配置、命令与参数时，应通过实际读取的来源核验。
- 引用必须指向读取过的资料；无法支持结论时不得仅附上看似相关的链接。
- 交互模拟需要说明假设、简化项与适用范围。
- 无法可靠生成交互时，提供普通讲稿或部分结果，并解释限制。

## 4. 信息架构

| 页面 | 主要内容 |
| --- | --- |
| 首页 | 新建学习主题、最近学习、生成任务；后续增加到期复习 |
| 主题工作台 | 学习目标、课程大纲、章节状态、主要参考资料 |
| 讲稿阅读页 | 目录、讲解、代码、交互演示、引用、验证摘要 |
| 生成任务详情 | 阶段、耗时、错误与修复摘要、产物版本 |
| 练习页（M2） | 生成参数、作答、评分、解析、历史 |
| 复习面板（M2） | 已确认计划、到期任务、完成记录 |
| 音频面板（M3） | 听觉讲稿、生成任务、播放器、播放进度 |

首版验证详情可折叠展示。普通阅读流程不要求用户理解模型、工具协议或追踪字段。

## 5. 主流程

1. 用户输入主题，可补充学习目标、基础、深度和技术版本。
2. 系统处理歧义，搜索并读取资料，生成可修改的课程大纲。
3. 用户确认大纲，选择章节并点击生成。
4. 系统形成结构化教学规格，决定是否需要交互演示。
5. 系统生成讲稿和演示，在隔离环境中运行并验证。
6. 对可修复错误执行局部修改与复验，达到次数或预算上限后停止。
7. 用户查看讲稿、操作演示、阅读来源与验证摘要。
8. 后续阶段，用户按需发起练习、复习和音频操作。

## 6. Milestone 1 功能需求

### FR-01 创建学习主题

必填：主题。选填：学习目标、已有基础、深度、版本、参考链接。

- 无关键歧义时直接开始，采用可见且可修改的默认设定。
- 对同名技术、明显过宽或目标冲突的输入提供简短澄清。
- 用户可编辑目标；修改不静默改写已有讲稿。
- 首版采用个人工作区，不将注册、组织管理或多人协作作为交付前置条件。

验收：仅填写主题即可完成后续流程；自定义基础和目标能够体现在课程规格中。

### FR-02 搜索、读取与资料管理

- 根据主题与目标生成搜索策略，调用 Web Search 并读取选定页面正文。
- 优先官方文档、项目仓库、标准与原始论文，其他来源标注类型。
- 记录 URL、标题、读取时间、文档版本（可识别时）、正文快照或摘要及其标识。
- 搜索结果片段不得直接视为已读取正文。
- 网页内容作为外部资料处理，不得改变系统权限或触发无关工具调用。
- 来源不足、冲突或访问失败时显示状态，允许补充资料、重试或缩小目标。
- 提供检索与正文缓存，缓存更新策略可配置。

验收：用户能够从关键内容跳转到对应来源；来源失败不会被伪装成已核验。

### FR-03 大纲与教学规格

课程大纲包含章节、目标、前置知识和知识点。用户可编辑、删除、排序和确认。

生成章节前形成可校验的规格，至少包含：

- 学习目标、读者基础、范围与版本。
- 知识点 ID、核心解释、示例、常见误区、引用映射。
- 是否需要交互，以及采用交互的教学目的。
- 交互的输入、可见状态、操作、预期行为和边界条件。
- 模拟假设、确定性检查项和无法自动验证的内容。

规格使用 Schema 校验。字段缺失时有限修正；依旧不合法则停止该阶段并保留错误。

验收：后续渲染、验证与版本关联使用同一份规格；无须交互的章节可生成普通讲稿。

### FR-04 HTML 讲稿与交互内容生成

- 讲稿包含目标、概念解释、示例、误区、总结和来源。
- 首版采用稳定阅读布局，允许模型生成受限的 HTML/CSS/JavaScript 或组件逻辑。
- 固定布局负责目录、引用、任务状态等公共功能；模型生成内容负责教学表达与交互。
- 支持至少两类可复用交互形式，例如逐步状态演示、参数调整与结果变化。
- 不将所有内容限制成少数预写演示；至少存在模型生成并可被修复的交互逻辑路径。
- 不支持的依赖或复杂需求应降级，不能未经允许加载任意外部包。
- 支持代码复制、章节导航和页面刷新后恢复。

验收：用户改变输入后能观察到相关状态或结果变化；模型生成内容与平台主应用隔离。

### FR-05 隔离运行

- 使用独立预览来源或等效的隔离方案，限制生成内容访问主站数据。
- 预览环境不持有模型密钥、数据库凭证或用户登录凭证。
- 默认禁止生成页面访问网络、读取主站存储和执行任意后端命令。
- 平台传入的学习内容与返回的验证消息遵循明确协议并校验来源与结构。
- 设置页面加载与操作超时；无响应预览可终止并重新创建。
- 首版不运行任意构建脚本；若后续开放包安装或服务端执行，需升级为容器或虚拟机级隔离。

验收：生成页面不能读取测试用主站存储标记或未授权外部资源；死循环或超时不阻塞主站操作。

### FR-06 浏览器验证

验证分为四层，报告分别记录结果，不合并为“全部正确”的单一结论。

| 层级 | 检查内容 | 首版方式 |
| --- | --- | --- |
| 加载与运行 | 页面打开、初始化、关键脚本异常 | 浏览器日志、加载状态、超时检查 |
| 交互行为 | 点击、输入、重置、状态变化 | 浏览器操作与 DOM/状态断言 |
| 技术语义 | 结果是否符合已知规则 | 固定评测案例的独立参考实现和断言 |
| 呈现 | 核心内容可见、明显溢出、桌面与移动尺寸 | 自动布局检查，必要时截图审查 |

- 自动生成的测试可用于日常自检，但不作为唯一评测依据。
- 固定案例的关键断言与预期结果由开发者维护，修复 Agent 无权修改。
- 任意开放主题可以验证运行和交互；未配置独立语义检查时明确标记“语义未自动验证”。
- 保存操作步骤、错误、断言结果和关键截图。
- 截图模型审查为可选增强，不作为 M1 必须依赖。

验收：能够发现预设的运行错误、无效按钮和错误状态变化，并分别归因。

### FR-07 反馈驱动的局部修复

- 输入为当前教学规格、当前代码、失败步骤、运行日志及相关断言。
- 优先修改相关代码；保持学习目标、来源和其他有效交互不变。
- 每次修复保存新版本，并再次执行必要检查和已有回归检查。
- 默认最多自动修复 2 轮，即初次生成后最多再生成 2 个修复版本；上限可配置。
- 设置任务耗时与调用预算，任一上限达到时终止自动修复。
- 不允许删除检查、伪造验证结果或修改独立参考答案来获得通过。
- 无法修复时交付可用的部分内容，标明失败交互，提供用户主动重试入口。

验收：至少一个固定失败案例能够展示“错误证据—代码修改—复验”的完整轨迹；同时展示停止条件有效的失败案例。

### FR-08 内容局部修改与版本

- 用户可要求简化解释、增加示例或修改单个演示。
- 每次修改建立新版本，保留旧版本和关联验证结果。
- 修改后的版本重新执行相关检查。
- 旧版本引用和验证报告不能直接作为新版本验证证据。
- M1 支持查看与切换版本，复杂差异对比可延后。

### FR-09 任务状态与观测

- 任务阶段：检索、规划、生成、验证、修复、完成。
- 任务状态：排队、运行中、成功、部分成功、失败、已取消。
- 支持取消、刷新恢复、主动重试；重复提交使用请求标识去重。
- 重试关联到原任务，避免覆盖原失败证据。
- 追踪检索、模型调用、浏览器操作、验证和修复阶段。
- 记录耗时、调用次数、模型版本、Token 用量与可获取的费用；未知费用标为未知。
- M1 先限制单个活动浏览器任务并排队，避免将高并发调度引入首轮范围。

## 7. Milestone 1 评测与验收

### 7.1 评测集

首版目标建立至少 20 个固定案例，覆盖至少 4 类主题，例如算法、缓存、监控和前端机制。包含正常交互、边界输入、无需交互、资料不足和不支持能力等情形。

每个案例包含：用户输入、固定资料快照、预期学习目标、关键行为、独立检查项、边界条件与人工语义检查表。

分开运行两种评测：

- 内容与生成评测：固定资料、模型版本和预算，减少检索变化造成的干扰。
- 端到端评测：真实搜索，单独记录来源获取成功率与版本变化。

选择部分案例作为开发时不查看答案的保留集。评测规模较小，报告应披露案例数和通过数量，避免泛化为所有主题的成功率。

### 7.2 对比方案

| 方案 | 内容 |
| --- | --- |
| A | 使用相同教学规格直接生成，不采用浏览器反馈修复 |
| B | 使用相同教学规格生成，并执行浏览器验证与最多 2 轮修复 |

两个方案使用相同模型、资料和初始条件；记录 B 的额外计算开销。保存初始产物，使结果可以追溯。资源允许时进行重复运行并披露波动。

### 7.3 指标定义

| 指标 | 定义 |
| --- | --- |
| 首次运行通过率 | 初次产物通过运行检查的案例数 / 全部案例数 |
| 首次行为通过率 | 初次产物通过独立行为检查的案例数 / 有该检查的案例数 |
| 修复后行为通过率 | 最终版本通过独立行为检查的案例数 / 有该检查的案例数 |
| 条件修复成功率 | 初次失败、修复后通过的案例数 / 初次失败且尝试修复的案例数 |
| 修复回归率 | 修复引入原先已通过检查失败的案例数 / 尝试修复的案例数 |
| 语义检查通过率 | 通过独立语义检查的案例数 / 具有语义检查的案例数 |
| 引用支持情况 | 人工抽查关键结论是否被对应来源支持，披露抽样数 |
| 时间与成本 | 首次生成与完整流程分别统计中位耗时、P95、调用次数与费用 |

所有百分比同时报告分子与分母。P95 在小样本中仅作为本批次描述。内容通过率与学习效果不混为一谈。

### 7.4 M1 发布门槛

以下为计划验收要求，不是已经取得的结果：

1. 端到端流程可运行，用户可以输入新主题、确认大纲并得到讲稿。
2. 至少两类交互形式，至少一条模型生成交互逻辑的路径。
3. 浏览器真实执行，并有独立于生成模型的行为断言。
4. 有自动修复、复验、回归检查、停止与降级机制。
5. 固定案例中的隔离和停止条件检查全部通过；有已知缺陷须修复后再发布。
6. 完成不少于 20 个案例的 A/B 评测，完整报告失败、成本和耗时。
7. 若 B 未优于 A，不宣称质量提升；分析原因并说明浏览器验证的实际价值与限制。
8. 提供在线或本地一键启动 Demo、README、架构说明、评测报告和演示视频。

M1 不要求预设的漂亮成功率。结果能被复查、缺陷被如实披露，优先于为指标缩减测试。

## 8. Milestone 2 练习与手动复习

### FR-10 手动生成练习

- 用户选择章节、知识点或已有错题范围，设置题量、难度和题型后生成。
- 支持单选、多选、简答与场景分析；题目关联知识点和讲稿版本。
- 提交前不展示答案。客观题确定性评分，开放题依据评分规则评分并支持反馈。
- 检查题目可答性、答案一致性和歧义；可执行题不在本阶段强制范围内。
- 保存题目与作答历史，不因答错自动生成新题。
- 用户主动发起“针对错题生成练习”时才创建新任务。

验收：用户可完成生成、作答、解析、历史回看；错误或歧义题可反馈并重新检查。

### FR-11 手动安排复习

- 用户选择范围，指定日期或请求系统提出间隔建议。
- 建议经确认才保存，支持修改、取消、完成及逾期状态。
- 任务形式包括回看讲稿、重做已有练习和自我回忆检查。
- 答题表现可参与建议，但不自动修改已确认日期。
- 到期不生成题目、讲稿或音频；用户主动点击后才生成新内容。
- 完成后提供“安排下一次”入口，不自动续建。
- 首版仅站内提醒，不默认发送邮件或推送。

### FR-12 学习状态

- 区分用户声明、阅读行为、答题表现、复习完成和音频收听。
- 不将完成阅读或播放直接判为掌握。
- AI 推断薄弱点时保留依据，允许用户纠正。
- 讲稿更新时标记关联内容可能过期，保留历史记录，不自动重建。

M2 验收：三个自动事件——读完、答错、复习到期——均不会隐式创建生成任务；计划日期与时区正确。

## 9. Milestone 3 手动音频生成与移动体验

### FR-13 听觉讲稿与语音合成

- 用户主动选择内容范围、完整讲解/重点总结/提问回忆模式、目标时长和可用音色。
- 先生成可编辑的听觉讲稿，用户确认后再发起音频合成。
- 对代码、表格与图示进行适合收听的解释，避免逐字符朗读。
- 音频关联章节、知识点和版本，保存段落与文本映射。
- 支持播放、暂停、倍速、跳转、断点续播及移动端后台播放。
- 浏览器或系统限制后台播放时明确说明实际支持情况。
- 用户主动重生成后保留旧音频；生成失败可重试。
- 播放完成只记为已收听，不自动创建练习或复习。

M3 验收：在明确列出的桌面与移动测试环境中验证播放行为；核对听觉讲稿与原内容的关键条件一致性。

## 13. 非功能需求

### 13.1 安全与数据

- 用户输入、网页资料与模型生成内容均作为不可信数据处理。
- 搜索抓取限制协议与目标地址，避免访问本机、私网和云元数据地址。
- 模型与工具密钥仅保留在服务端，日志进行脱敏。
- 生成页面隔离、网络限制和执行超时属于 M1 必须完成的要求。
- 支持删除主题及关联产物；后续多用户发布时落实所有者访问控制。
- 浏览器日志、截图与搜索快照设置可配置保留期限。

### 13.2 性能与成本

- 长任务采用异步执行，阶段变化及时呈现；前端不得等待单个长连接才获得最终结果。
- 使用阶段超时、修复上限、请求去重和可配置预算控制消耗。
- 分别测量排队时间、执行时间与端到端耗时。
- 模型与 TTS 供应商费用未知时不显示伪精确金额。
- M1 按实际机器配置报告容量，不宣称未经测试的高并发能力。

### 13.3 可访问性与兼容性

- 阅读页支持基本键盘操作、可见焦点、图表文字说明。
- 关键信息不能仅用颜色表达。
- M1 至少测试一个桌面尺寸和一个移动尺寸，记录浏览器版本。
- 交互不适合小屏时提供明确提示和文字解释，不阻塞阅读。

## 14. 异常处理

| 异常 | 预期行为 |
| --- | --- |
| 主题含糊 | 请求最少必要澄清，保留已填信息 |
| 搜索或正文读取失败 | 标明失败来源，允许补充或重试 |
| 资料冲突或版本不明 | 标注差异，必要时确认版本 |
| 规格不合法 | 有限修正，失败后停止，不生成伪成功产物 |
| 页面无法运行 | 收集证据、尝试修复，超限后部分交付 |
| 语义未覆盖 | 标为未自动验证，不能展示为语义通过 |
| 模型尝试修改测试 | 拒绝修改，保留事件与原测试 |
| 任务超时或费用超限 | 停止后续调用，保留已有结果 |
| 用户取消 | 停止可取消步骤，隔离执行环境回收 |
| Worker 中断 | 恢复任务状态或明确失败，避免重复计费调用 |
| 内容更新 | 标记关联内容版本状态，等待用户主动重建 |

## 15. 里程碑与交付物

### Milestone 1 交互生成与执行反馈闭环

优先级最高，对当前简历的新增价值最大。

包含 FR-01 至 FR-09，以及评测、隔离与基本可靠性要求。交付：

- 可运行产品：输入主题、大纲确认、按章节生成、交互操作、验证与修复摘要。
- 可复查证据：结构化规格、初始与修复版本、浏览器操作、独立断言、截图与运行日志。
- 评测报告：不少于 20 个案例的直接生成/反馈修复对比，包含失败与成本。
- 展示材料：启动说明、架构与取舍说明、演示视频、已知限制。

建议内部顺序：

1. 先完成一个端到端垂直案例：生成页面、浏览器执行、独立断言。
2. 接入修复、复验、停止条件和隔离检查。
3. 接入资料读取、大纲确认与开放主题输入。
4. 扩展跨主题评测、页面体验与交付文档。

阶段 1 的单案例是开发切片，不是产品领域限制。M1 完成前不优先建设练习中心、复习算法或音频播放器。

### Milestone 2 练习与复习闭环

包含 FR-10 至 FR-12。交付手动练习、作答反馈、学习记录、手动确认的复习计划与站内面板。补充题目质量、判分与日期状态测试。

### Milestone 3 音频与移动使用

包含 FR-13。交付听觉讲稿预览与编辑、手动合成、基础播放器、后台播放兼容验证与断点续播。

### 后续候选

真实代码或查询执行练习、交互模板扩展、个性化策略、用户反馈驱动的质量优化。需依据使用情况决定，不作为前三阶段前置条件。

## 16. 风险与取舍

| 风险 | 应对与范围控制 |
| --- | --- |
| 开放主题导致质量波动 | 产品开放输入，明确评测覆盖和验证等级；不支持时降级 |
| 模型生成测试与答案共同出错 | 固定案例采用独立参考实现、人工检查与保留集 |
| 浏览器检查通过但知识有误 | 区分运行、行为和语义状态，核验关键资料 |
| 任意前端代码增加隔离难度 | 限制依赖与执行能力，主站与预览分离 |
| 修复循环增加费用却无收益 | 限次、预算与 A/B 测量，失败如实报告 |
| 为功能数量延误新增技术亮点 | M1 只围绕生成—执行—修复—评测交付 |
| 新项目仍与求职助手重叠 | 简历与展示重点放在生成代码、浏览器证据和独立验证 |
